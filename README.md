# ECMWF US TDD

Скрипт загружает прогноз температуры ECMWF IFS через официальный
`ecmwf-opendata`, сохраняет исходные температуры в SQLite, считает дневные
HDD/CDD/TDD по девяти регионам США и выгружает результат в CSV.

Работает с континентальными США (CONUS, без Аляски и Гавайев). В первой версии
используется приближение: 36 крупных городов и заданные вручную веса населения.
Индекс не является официальным продуктом ECMWF/NOAA или индексом потребления газа.

## Быстрый запуск

Нужен Python 3.11 или новее. Команды выполняются из папки репозитория.

```bash
git clone https://github.com/Blobik1/ecmwf-us-tdd.git
cd ecmwf-us-tdd
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe ecmwf_tdd.py collect
```

Linux/macOS:

```bash
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python ecmwf_tdd.py collect
```

`collect` сам выбирает последний доступный прогон с полным запрошенным
горизонтом 15 дней. Поиск проверяет конечный срок +360 часов. Результаты:

```text
data/weather.sqlite              база с накопленной историей запусков
data/raw/                        скачанные GRIB и их контрольные суммы
data/export/daily_national.csv    дневные HDD/CDD/TDD США для всех сохранённых запусков
data/export/daily_regions.csv     результаты девяти регионов
data/export/daily_temperatures.csv  Tmin/Tmax и градусо-дни каждого города
data/export/run_comparison.csv    изменение между двумя последними запусками
data/export/summary.json          итог выбранного запуска (export: последнего по времени модели)
data/export/used_config.json      точные настройки и веса этой выгрузки
```

CSV в UTF-8 с BOM, разделитель — запятая, десятичная точка. Их можно открыть
в Excel через «Данные → Из текста/CSV», выбрав разделитель. База открывается
любым инструментом SQLite, например DB Browser for SQLite.

API-ключ ECMWF для этой открытой выдачи не требуется. При проблемах основного
сервера можно выбрать публичную копию:

```bash
python ecmwf_tdd.py collect --source aws
```

В [examples/](examples/) сохранён пример реальной проверки: прогон
22.11.2026 00 UTC, полные сутки 22 ноября — 6 декабря, 15 дней.
Получено HDD **220.84**, CDD **8.59**, TDD **229.43** °F·день при конфиге
`approx-population-v1`. Это фиксированный пример прогноза на дату запуска,
а не текущая сводка. Повторный запуск по тому же кешу не создал дублей:
в SQLite остались 6 048 исходных температурных значений, 540 городских суток
и 150 региональных/национальных дневных индексов.

## Нужная дата, цикл и горизонт

```bash
python ecmwf_tdd.py collect --date 2026-11-22 --cycle 0 --days 15
python ecmwf_tdd.py collect --cycle 12 --days 15
python ecmwf_tdd.py collect --cycle 6 --days 6
python ecmwf_tdd.py export --out data/another-export
```

`--date` задаёт дату **инициализации модели**, а не дату прогнозируемой погоды,
и требует `--cycle`. Возможны 0, 6, 12 и 18 UTC. В открытой выдаче IFS 00/12 UTC
доступны сроки до 360 часов, 06/18 UTC — до 144 часов. Запросить 15 дней у
06/18 UTC нельзя: скрипт завершится с понятной ошибкой.

Указанная в примере дата должна ещё присутствовать у выбранного источника.
Основной портал хранит короткий rolling archive. Скрипт накапливает собственную
историю **с момента запуска**, а не восстанавливает многолетние прогнозы.
Для большой истории существуют TIGGE/ECDS, для реанализа погоды — ERA5/CDS.

## Как считается индекс

Используются родные интервальные экстремумы модели, а не минимум и максимум
нескольких мгновенных замеров:

- `mn2t3/mx2t3`: минимальная/максимальная температура на высоте 2 м за 3 часа,
  сроки до +144 часов;
- `mn2t6/mx2t6`: то же за 6 часов, сроки +150…+360 часов.

Для каждого города берётся ближайший узел глобальной сетки 0.25°.
Из всех интервалов полных суток 00:00–24:00 UTC собираются Tmin и Tmax.
Время инициализации, параметр, единицы, интервалы, геометрия сетки и наличие
каждого нужного поля проверяются до записи результатов.

GRIB хранит значения с конечной точностью. Минимум и максимум, упакованные
отдельно, могут слегка поменяться местами в пределах `packingError` двух
полей. Исходные значения и их погрешность сохраняются в SQLite. Большое
нарушение порядка вызывает ошибку. Если суточные экстремумы остаются
корректными, они используются без изменения (`quality=interval_packing_overlap`).
Если даже суточные экстремумы перекрываются в пределах заявленной точности,
используется их общая середина (`quality=daily_packing_overlap`). Остальные
строки имеют `quality=ok`.

```text
Tmean_F = ((Tmin_K + Tmax_K) / 2 - 273.15) * 1.8 + 32
HDD = max(base_F - Tmean_F, 0)
CDD = max(Tmean_F - base_F, 0)
TDD = HDD + CDD

HDD_region = sum(city_weight * HDD_city)
CDD_region = sum(city_weight * CDD_city)
HDD_US = sum(region_weight * HDD_region)
CDD_US = sum(region_weight * CDD_region)
TDD_US = HDD_US + CDD_US
```

База по умолчанию — 65°F. Единица результата — °F·день. За неделю или другой
период складываются **дневные** индексы. Температурный порог применяется к
каждому городу до географического усреднения. Значения не округляются перед
суммированием.

Для запуска 00 UTC горизонт 15 дней даёт 15 полных суток UTC. Для запуска
12 UTC тот же горизонт содержит 14 полных календарных суток. Для запуска
06 UTC на 6 дней остаются 5 полных суток. Первый и последний неполные дни
исключаются; скрипт не достраивает их нулями или данными другого запуска.

## Приблизительные коэффициенты регионов

Это вручную выбранные оценки доли населения, а не официальная статистика.
Сумма равна 1. В каждом регионе есть несколько городов с собственными весами.
Все координаты и коэффициенты находятся в [regions.json](regions.json).

| Регион | Коэффициент | Доля |
|---|---:|---:|
| New England | 0.050 | 5.0% |
| Middle Atlantic | 0.120 | 12.0% |
| East North Central | 0.140 | 14.0% |
| West North Central | 0.065 | 6.5% |
| South Atlantic | 0.210 | 21.0% |
| East South Central | 0.060 | 6.0% |
| West South Central | 0.130 | 13.0% |
| Mountain | 0.080 | 8.0% |
| Pacific CONUS | 0.145 | 14.5% |
| **Сумма** | **1.000** | **100.0%** |

Чтобы изменить веса или базу, отредактируйте `regions.json`, измените его
`version` и снова выполните `collect`. Настройки проверяются: коэффициенты
должны быть положительными и суммироваться в 1, идентификаторы — уникальными.
Хеш всего конфига хранится в БД, поэтому разные методики не смешиваются.
Существующие скачанные GRIB могут использоваться повторно с новыми весами.

## История, повторные запуски и сравнение

Каждый запуск модели и каждая версия конфигурации имеют отдельные ключи.
Повторная загрузка одного прогона не создаёт дублей. Более короткий повторный
запрос не удаляет уже сохранённый длинный прогноз. Загрузка и проверка выполняются
до транзакции записи: неполный или неверный набор не заменит хорошие данные.

`run_comparison.csv` сравнивает выбранный прогон с ближайшим более ранним
сохранённым прогоном **для одного конфига** только по совпадающим датам.
Команда `export` выбирает последний запуск по времени инициализации.
Формула — новый индекс минус старый.
Поскольку длина и начало прогнозов могут отличаться, разность полных сумм
двух запусков часто не равна сумме корректных дневных пересмотров.
Если сохранён только один запуск, CSV содержит только заголовок, а значение
`delta_tdd_same_dates` в JSON равно `null`.

SQLite содержит:

| Таблица | Содержимое |
|---|---|
| `runs` | Время инициализации, модель и первое время записи |
| `configurations` | Полный JSON настроек и его SHA-256 |
| `collections` | Собранный горизонт и число полных суток |
| `raw_files` | Файлы GRIB, SHA-256, источник, запрос и время загрузки |
| `temperature_samples` | Температуры городов в K по исходным интервалам модели |
| `daily_temperatures` | Суточные экстремумы, среднее и DD городов |
| `daily_indices` | HDD/CDD/TDD регионов и строка `CONUS` |

Пример запроса:

```sql
SELECT run_time_utc, valid_date_utc, hdd, cdd, tdd
FROM daily_indices
WHERE region_id = 'CONUS'
ORDER BY run_time_utc DESC, valid_date_utc;
```

Время скачивания не является точным временем появления прогноза на рынке.
Для строгого исторического теста потребуется отдельно фиксировать фактическое
время доступности данных. Суточные границы UTC отличаются от местных суток
и от газового дня.

## Запуск на GitHub без локальной установки

Откройте **Actions → Collect ECMWF → Run workflow**. Выберите горизонт,
источник и, если требуется, цикл. После успешного запуска скачайте артефакт
**ecmwf-tdd-data**: там находятся SQLite и CSV.

Перед новым запуском workflow восстанавливает последнюю неистёкшую базу из
артефактов, поэтому история продолжается. Одновременные сборщики выполняются
последовательно. Артефакты хранятся 90 дней; без сохранившегося артефакта
создаётся новая база. Для долговременного архива держите локальную резервную
копию или перенесите БД в постоянное хранилище. Большие GRIB не загружаются
в GitHub и не входят в артефакт workflow.

Автоматического расписания в этой версии нет: workflow запускается вручную.
Для регулярного локального сбора можно запускать ту же команду через cron
или Планировщик заданий Windows, сохраняя одну и ту же папку `data`.

## Проверки

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
ruff check .
```

Тесты проверяют формулы, применение порога до усреднения, неполные сутки,
пропуски и дубли интервалов, сумму весов, транзакционность и повторные записи
SQLite, сохранение длинного горизонта, общие даты сравнения и повреждённый кеш.
В GitHub Actions тесты запускаются на Python 3.11, 3.12 и 3.13 без сети ECMWF.

## Ограничения и источники

36 городов приближают погоду регионов. Плотность населения, высота, береговые
эффекты и фактические газовые потребители внутри регионов учтены грубо.
У одного HDD и одного CDD разные связи с потреблением газа. Этот TDD не
переводится напрямую в Bcf/day. Ансамбль ENS и климатические нормы пока
не рассчитываются. Это понятная стартовая версия для изучения и расширения.

- [Официальный клиент ecmwf-opendata](https://github.com/ecmwf/ecmwf-opendata)
- [ECMWF Open Data и доступные параметры](https://www.ecmwf.int/en/forecasts/datasets/open-data)
- [Определение градусо-дней EIA](https://www.eia.gov/energyexplained/units-and-calculators/degree-days.php)
